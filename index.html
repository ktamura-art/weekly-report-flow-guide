CSVから「列だけ」作る

データは入れません。行はフローがOutlookから入れるものだけにします。取り込むCSVは見出し1行のみです。

あとで週次の自動実行に切り替えるとき

トリガーを［スケジュール済みクラウド フロー］に差し替えます。開始日時＝直近の金曜17:00、繰り返し＝1週間、実行日＝金曜のみ。

そのときタイムゾーンを必ず設定します。 トリガーの［詳細オプションを表示］でタイムゾーンを (UTC+09:00) Osaka, Sapporo, Tokyo に。 既定はUTCのため、金曜17時のつもりが土曜2時に動きます。
②

WeekStart（作成） 完了

［データ操作］→［作成］。アクション名を WeekStart に変更し、fx に貼り付けます。

concat(formatDateTime(addHours(addDays(startOfDay(convertFromUtc(utcNow(),'Tokyo Standard Time')),sub(mod(sub(12,dayOfWeek(convertFromUtc(utcNow(),'Tokyo Standard Time'))),7),7)),-9),'yyyy-MM-ddTHH:mm:ss'),'Z')
③

WeekEnd（作成） 完了

同じく［作成］。アクション名を WeekEnd に。

concat(formatDateTime(addHours(addDays(startOfDay(convertFromUtc(utcNow(),'Tokyo Standard Time')),mod(sub(12,dayOfWeek(convertFromUtc(utcNow(),'Tokyo Standard Time'))),7)),-9),'yyyy-MM-ddTHH:mm:ss'),'Z')
式の読み方。convertFromUtc で日本時間にし、実行日から見て直近の金曜0:00を求め、 その7日前を開始、当該金曜を終了としています。最後の addHours(-9) でUTCに戻し、 concat で末尾に Z を付けています。 月曜から金曜のどの日に実行しても、同じ1週間（金曜スタート・木曜締め）を取得します。
末尾の Z は必要です。 convertFromUtc の戻り値にはタイムゾーンの表記が付かないため、 予定取得アクションがUTCとして解釈しないことがあります。 formatDateTime の書式文字列に Z を直接書くと解釈が不安定なため、concat で外から足しています。
アクションは［変数を初期化する］ではなく［作成］で構いません。 1アクションで済み、参照は outputs('WeekStart') になります。 先頭の @ は不要です（fxの入力欄では付けません）。

テストと確認

  1. 右上の［保存］
  2. ［テスト］→［手動］→［テスト］→［フローの実行］
  3. 各アクションが緑のチェックになることを確認
  4. SharePointリストを開き、行が入っていることを確認
  5. もう一度実行して、行が増えないことを確認（重複防止の動作確認）
5まで通れば完成です。以降は何度テストしても行が重複しません。

失敗したときの見方

［マイ フロー］→ フロー名 → 実行履歴から、赤くなったアクションをクリックすると入力・出力・エラーメッセージが見られます。

「入力」を見るのがコツです。 実際に送られた値が分かるので、式の結果が意図どおりかを確認できます。 出力だけ見ても原因にたどり着けないことが多いです。

取得件数が0件のとき

エラーではありません。 For each が緑のチェックで0秒、中のアクションが灰色のダッシュなら、 対象期間にその予定表の予定が無かったというだけです。 ④の出力を開いて value が [] かどうか確認してください。
